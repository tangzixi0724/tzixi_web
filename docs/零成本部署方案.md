# 零成本部署方案

目标：`tzixi.cn` 上线一个展示 Minecraft 模组的网站，访客能浏览、能点下载，**全程不花一分钱**（域名续费除外，因为域名你已经有了）。

## 结论：三条链路各司其职

| 环节 | 用什么 | 为什么是它 |
| --- | --- | --- |
| 站点托管 | **Vercel Hobby**（免费） | 静态文件走全球 CDN，绑自定义域名免费，HTTPS 证书自动续。Git push 即部署，PR 自动出预览链接。 |
| 源码 | **GitHub 公开仓库** | 免费，且是 Vercel 的部署来源。 |
| 安装包 / 配置文件 | **GitHub Releases** | 单文件上限 2 GB（普通仓库单文件 100 MB），下载带宽**不计费、不限量**，还自带每个文件的下载计数。 |
| 字体 | 自托管进仓库（101 片按需加载） | 不请求第三方 CDN，国内访问稳定、不泄露访客 IP；浏览器只拉当前页面用到的分片。 |
| 域名 | 你自己的 `tzixi.cn` | 只改两条 DNS，不产生额外费用。 |

关键是**大文件绝不能进 Vercel**。Vercel 免费版有三个相关限制：

- 单次部署上传的静态文件总量 **100 MB**（[Limits](https://vercel.com/docs/limits)）
- 每月 Fast Data Transfer **100 GB**（[Hobby](https://vercel.com/docs/plans/hobby)）
- 超额不是扣钱，而是**功能被暂停到 30 天后**

模组 jar 一旦塞进 `public/`，部署体积和下载流量会同时撞这两个上限。放到 GitHub Releases，站点本体只有 ~5 MB（其中 4.7 MB 是中文字体切片），下载流量完全走 GitHub 的 CDN，Vercel 那边的 100 GB 只用来送 HTML/CSS/JS 和字体。

按站点体积 300 KB 估算（首次访问，含字体），100 GB ≈ **33 万次页面访问/月**。个人作品站基本不可能碰到。

## 免费额度够不够（真实数字）

| 指标 | 免费额度 | 本站实测/估算 | 余量 |
| --- | --- | --- | --- |
| 部署体积 | 100 MB | 5.1 MB | 20× |
| 页面出站流量 | 100 GB/月 | 约 0.3 MB/次访问 | 够 33 万次访问 |
| 函数调用 | 100 万次/月 | **0 次**（没有后端） | 用不到 |
| 构建 | 100 次部署/日 | 你 push 几次就几次 | 用不到 |
| Release 单文件 | 2 GB | 单个模组通常 < 5 MB | 400× |

## 首屏体积（实测）

| 资源 | 体积 |
| --- | --- |
| JS（React + 全部内容） | 246 KB → gzip **80 KB** |
| CSS（全部样式 + 101 条字体声明） | 109 KB → gzip **38 KB** |
| 字体分片（首屏实际请求 20 片） | 约 **1.1 MB** |
| 合计 | 约 1.5 MB，gzip 后约 1.2 MB |

字体占了大头。想要更快，把 `src/styles/global.css` 里 `--font-ui` 的 `'Noto Sans SC'` 删掉、改走系统字体，首屏立刻降到约 400 KB——代价是不同系统字形略有差异。这是一行改动，随时可切。

所有字体与静态资源都带 `Cache-Control: public, max-age=31536000, immutable`（见 `vercel.json`），第二次访问不再请求。

## 一次性配置（约 15 分钟）

### 1. 推代码

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/tangzixi0724/tzixi_web.git
git push -u origin main
```

### 2. 导入 Vercel

打开 [vercel.com/new](https://vercel.com/new) → 用 GitHub 登录 → Import `tzixi_web`。

`vercel.json` 里已经写好了，面板上不需要改任何东西：

```json
{
  "framework": "vite",
  "installCommand": "bun install",
  "buildCommand": "bun run build",
  "outputDirectory": "dist"
}
```

Vercel 会读 `bun.lock` 自动用 Bun 跑安装和构建（[Bun runtime 支持](https://vercel.com/docs/functions/runtimes/bun)，静态站只需要 Bun 作包管理和构建工具）。点 Deploy。

### 3. 绑域名 `tzixi.cn`

Vercel 项目 → Settings → Domains → 输入 `tzixi.cn` → Add。然后去域名注册商（阿里云 / 腾讯云 / Cloudflare 都行）加记录：

| 类型 | 主机记录 | 记录值 | 说明 |
| --- | --- | --- | --- |
| A | `@` | `76.76.21.21` | 裸域名，Vercel 官方推荐值 |
| CNAME | `www` | `cname.vercel-dns.com` | www 跳转到裸域 |

> **以 Vercel 面板上显示的值为准**——它有时会给不同的 IP 或 `cname.vercel-dns-0xx.com`。填错不会报错，只会一直停在 "Invalid Configuration"。

DNS 生效通常 1–10 分钟，证书在生效后自动签发。不要开注册商的"域名转发/URL 跳转"，会和 A 记录打架。

如果域名 DNS 托管在 Cloudflare，把这两条记录的**代理状态关掉（灰云，仅 DNS）**，否则 Vercel 签证书会失败。

### 4. 上传文件

见 README 的「加一个模组」：每个作品建一个 Release，tag 用 slug，jar 拖进附件区，文件名和 `src/content/mods.ts` 里的 `fileName` 一字不差。之后再加新版本，往同一个 Release 里补文件即可，旧链接永远有效。

## 唯一需要留意的规则

Vercel 免费版**只允许非商业的个人使用**（[fair use guidelines](https://vercel.com/docs/limits/fair-use-guidelines)）。挂广告、卖下载、接赞助商就算商业用途。你这个是纯作品展示，完全在允许范围内。

## 如果以后不够用了，怎么换

代码和部署配置是解耦的，只需要换托管方，不碰一行业务代码：

| 触发条件 | 换到 | 改动量 |
| --- | --- | --- |
| 月流量长期 > 100 GB | **Cloudflare Pages**（静态请求不限量，商业用途也免费） | 改一次构建命令（`bun run build` → 输出 `dist`），DNS 换成 Cloudflare |
| 需要评论 / 下载计数 / 后台 | Vercel + **Supabase** 免费额度 | 加一个数据层，前端照旧 |
| 想让国内访问更快 | 阿里云 OSS + CDN（**要钱**，约 几元/月） | 备案 + 换托管，是唯一有成本的方案 |

换托管时域名不用动，只改 DNS 指向。

## 为什么不用别的免费方案

- **GitHub Pages**：免费且无限流量，但自定义域名只支持 CNAME（裸域要用 A 记录，GitHub 提供 4 个 IP），且不支持服务端重写/自定义响应头——`vercel.json` 里那套缓存策略和 `cleanUrls` 就用不上了。作为备选完全可行。
- **Netlify**：免费额度 100 GB/月，和 Vercel 同量级，功能等价。选 Vercel 只是因为它对 Bun 的检测更自然。
- **把 jar 放仓库里用 GitHub Pages 提供**：仓库单文件 100 MB、仓库建议总大小 < 1 GB 且不允许当 CDN 用，违反 GitHub 的使用条款。用 Releases 才是官方认可的发布渠道。
- **Cloudflare R2**：10 GB 存储 + 出站免费，是好方案，但要先绑卡（防滥用），对"一分钱不想花"的人来说多一道心理门槛。等文件超过 Releases 好管理的量再考虑。
